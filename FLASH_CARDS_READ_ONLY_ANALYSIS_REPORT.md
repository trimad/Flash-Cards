## 1. Executive Summary

Flash-Cards is a Hugo-powered static flashcard web application. It builds a static site with deck routes and serves all study data from JSON files under `static/assets`. The app runs entirely in the browser: there is no backend service, database server, account system, or API server.

Primary use case:

- Study flashcard decks for CompTIA certification prep and early reading practice.
- Current deck areas include:
  - CompTIA A+ route placeholders
  - CompTIA Network+
  - CompTIA Security+
  - Early Reading
  - CompTIA Tech+

Core capabilities:

- Deck library landing page
- Per-deck study interface
- Table of contents by chapter/section
- Card flipping
- Previous/next navigation
- Keyboard controls
- Gamepad controls
- Speech synthesis / optional card audio
- Sound effects
- Multiple-choice quiz cards
- Self-grading right/wrong controls
- Browser-local progress persistence
- Per-deck reset-progress action
- Theme settings modal with Evangelion palettes: Rei, Shinji, Asuka, NERV
- Responsive layout
- Headless browser smoke test harness

Important observed limitations:

- A+ routes exist but currently have no card files.
- Legacy Network+ objective decks have 393 cards whose `A` arrays are entirely blank.
- `TODO.md` explicitly lists unreferenced root/backup assets that need provenance/removal review.
- `public/assets/network-plus.json` exists and is zero bytes, while the source/static and docs copies do not exist. `public/` is gitignored and appears stale.
- `README.md` says GitHub Pages is served from `gh-pages`, but `.github/workflows/deploy.yml` uses GitHub Pages artifact deployment rather than pushing a `gh-pages` branch.
- Network+ front matter has `professorMeser` misspelled; the template expects `professorMesser`, so that link is not rendered for Network+ based on current template logic.

## 3. Architecture

High-level architecture:

The app is a static site generated by Hugo. Hugo reads content route files from `content/tests/*.md`, templates from `layouts/`, and static assets from `static/`. It emits a static deployable site into `docs/` for local branch-folder deployment, while GitHub Actions builds to `public/` during CI and uploads that as a Pages artifact.

Runtime architecture:

Browser:

- Loads generated HTML.
- Loads `css/flashcards.css`.
- Loads `js/theme-selector.js` globally.
- Loads `js/welcome-modal.js` globally.
- Loads `js/flashcards.js` only on deck/test pages.
- Fetches JSON:
  - `assets/menu.json`
  - deck JSON files referenced by the selected test/chapter
- Persists state in `localStorage`.
- Uses browser APIs:
  - `fetch`
  - `localStorage`
  - `history.replaceState`
  - `speechSynthesis`
  - `Audio`
  - `Gamepad API`
  - `requestAnimationFrame`
  - `matchMedia`
  - DOM APIs

Hugo build layer:

- `content/tests/*.md` define routes and front matter.
- `layouts/_default/baseof.html` defines global shell/header/settings modal.
- `layouts/index.html` defines homepage deck grid.
- `layouts/tests/single.html` defines flashcard study UI and injects `window.FlashCardsConfig`.
- `layouts/partials/welcome-modal.html` defines first-load welcome modal.

Data layer:

- JSON files under `static/assets`.
- No database.
- No server persistence.
- Browser progress stored in `localStorage`.

Backend/API layer:

- None at runtime.
- Static JSON files are fetched directly.
- Import scripts exist for scraping ExamCompass data, but they are offline/dev scripts, not part of the live app.

Deployment layer:

- Local: Hugo server or Hugo build.
- CI: GitHub Actions builds Hugo site and deploys to GitHub Pages.

5. Choose a deck.

1. Page loads deck shell.
2. Browser fetches `assets/menu.json`.
3. Browser resolves current test by `testIndex`/`testName`.
4. Browser fetches all referenced chapter deck files.
5. App picks initial section:
   - URL hash section/card if valid
   - otherwise first section with cards
   - otherwise first section
6. Current card displays front side.
7. User flips card to answer side.
8. User marks Right/Wrong or uses quiz controls if options are present.
9. App updates progress in localStorage.
10. User navigates previous/next or section buttons.
11. URL hash updates to preserve current section/card.

No browser workflow exists. A content author creates/updates:

- `static/assets/menu.json`

### Settings workflow

2. Dialog opens.
3. Choose theme.

### Studying
