# Architecture

Flash Cards is a static, browser-only flashcard platform generated by Hugo.

## Design principles

- Preserve static hosting and GitHub Pages compatibility.
- Keep all study data in portable JSON files.
- Store user progress locally in the browser.
- Avoid server dependencies, databases, accounts, and backend APIs.
- Use plain JavaScript modules loaded by Hugo templates.

## Build-time architecture

Hugo reads:

- `content/tests/*.md` for deck routes.
- `layouts/_default/baseof.html` for the shared shell.
- `layouts/index.html` for the deck library.
- `layouts/tests/single.html` for the study interface.
- `static/` for JSON decks, JavaScript, CSS, PWA assets, PDFs, fonts, and audio.

The generated site is emitted to `docs/`.

## Runtime architecture

At runtime the browser loads static HTML, CSS, and JavaScript. The app then fetches:

- `assets/menu.json`
- active deck JSON files referenced by the selected deck

There is no backend API. JSON files are the API.

## Main browser modules

- `static/js/flashcards.js`
  - Study UI
  - Deck loading
  - Controller panel focus: LB for Deck/TOC, RB for Study
  - Deterministic roving focus indexes for Deck, Study, and modal contexts
  - Modal-first controller routing so dialogs capture D-pad/A/B input
  - Progress persistence
  - Quiz/self-grade logic
  - SM-2 scheduling
  - Bookmarks/suspension
  - Shuffle/due review entry points
  - Speech synthesis and gamepad support

- `static/js/theme-selector.js`
  - Theme settings dialog
  - Theme persistence
  - Evangelion palette selection

- `static/js/welcome-modal.js`
  - First-run welcome modal
  - Dismissal persistence
  - Focus trap

- `static/js/global-search.js`
  - Ctrl+K global search
  - Deck/chapter/section/card index
  - Fuzzy search and highlighted results

- `static/js/deck-editor.js`
  - Local authoring dialog
  - Markdown-like and JSON parsing
  - Autosaved drafts
  - Undo/redo
  - JSON export

- `static/js/pwa.js`
  - Service worker registration

- `static/service-worker.js`
  - Core asset caching
  - Runtime caching for fetched static assets
  - Offline fallback

## Data flow

1. Hugo route injects `window.FlashCardsConfig`.
2. `flashcards.js` loads `menu.json`.
3. The selected deck is found by `testIndex` or `testName`.
4. Chapter deck files are fetched in parallel and cached by URL.
5. Cards are normalized into a common runtime shape.
6. User progress is read from localStorage.
7. Rendering updates the TOC, card, controls, progress, and URL hash.
8. Study actions update localStorage.

## Persistence

All user data is browser-local:

- Theme: `flashcards.evangelionTheme`
- Welcome dismissal: `flashcards.welcomeDismissed.v2`
- Deck progress: `flash-cards:<deck-slug>:progress:v1`
- Deck editor draft: `flashcards.deckEditorDraft.v1`

## Deployment

GitHub Actions runs `npm test`, which builds the Hugo site into `docs/`, validates the export, runs browser smoke tests, and deploys `docs/` through GitHub Pages artifact deployment.
